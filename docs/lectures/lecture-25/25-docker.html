The Dockerfile from Lecture 23

# Start from an official Python image
FROM python:3.14-slim

# Create /app inside the image and move into it
WORKDIR /app

# Copy requirements.txt from your computer
# into /app (the "."), then install it
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# Copy hello.py from your computer into /app
COPY hello.py .

# The command that runs when the container starts
CMD ["python", "hello.py"]
# Build an image called datasci350-example
# from the files in this folder
docker build -t datasci350-example .

# Start a container from the image, and
# delete the container when it exits
docker run --rm datasci350-example
  • FROM picks the base image, here Python 3.14 on a slim Debian Linux
    • Base images live on Docker Hub, where you can search for one
  • WORKDIR creates /app and runs every later step inside it
  • COPY brings a file from your folder into the image
  • RUN executes a command while the image is built
  • CMD sets the command the container runs when it starts
  • requirements.txt is copied before hello.py, so editing the script does not reinstall the packages
  • Today’s Dockerfile adds ENV, which sets a variable such as PATH, and SHELL, which picks the shell for RUN

The Dockerfile 🐳

The whole Dockerfile

# 1. Base image
FROM ubuntu:24.04

# 2. Environment and shell
ENV DEBIAN_FRONTEND=noninteractive
SHELL ["/bin/bash", "-c"]

# 3. System packages
RUN apt-get update && apt-get install -y [...]

# 4. Quarto
RUN ARCH=$(dpkg --print-architecture) && [...]

# 5. Python environment
RUN python3 -m venv /opt/venv
ENV PATH="/opt/venv/bin:$PATH"
COPY requirements.txt /project/requirements.txt
RUN pip install --no-cache-dir -r /project/requirements.txt

# 6. Project files
WORKDIR /project
COPY . /project

# 7. Default command
ENV QUARTO_PYTHON=/opt/venv/bin/python
CMD ["bash", "-c", "quarto render report.qmd && [...]"]
  • 13 instructions in seven blocks
  • The build log numbers eight of them, [1/8] to [8/8]
  • ENV, SHELL and CMD only record settings, so they get no number
  • The real file has a comment above every line. Read them before you change anything
  • Lecture 23’s file ran one script. This one installs Ubuntu packages, Quarto and a Python environment

Full listing

Blocks 1 and 2: FROM, ENV, SHELL

# We pin the tag to "24.04" rather than "latest".
# "latest" changes over time, and a base image
# that changes breaks reproducibility.
FROM ubuntu:24.04

# DEBIAN_FRONTEND=noninteractive stops apt-get
# from asking questions during the build.
# Nobody is at the keyboard to answer them.
ENV DEBIAN_FRONTEND=noninteractive

# Use bash for the RUN steps below. Docker uses
# the simpler "sh" shell by default.
SHELL ["/bin/bash", "-c"]
  • ubuntu:latest meant 24.04 last year and means 26.04 today, so we pin the tag
  • tzdata is the Ubuntu package that would otherwise stop and ask you for a time zone
  • ubuntu:24.04 is a 29MB download, 108MB once unpacked

hub.docker.com/_/ubuntu

  • ENV also applies when the container runs
  • SHELL makes every later RUN use bash, and -c passes it a string of commands
  • The ubuntu image has no Python, so block 3 installs it
  • Quarto ships as a .deb file, which needs a Debian-based system like Ubuntu

Block 3: RUN apt-get install

RUN apt-get update && apt-get install -y --no-install-recommends \
    ca-certificates \
    wget \
    git \
    python3.12 \
    python3.12-venv \
    python3-pip && \
    apt-get clean && rm -rf /var/lib/apt/lists/*
  • One RUN is one layer
    • Six RUN lines here would give six layers and a bigger image
  • Clean up in the same RUN: a later layer cannot shrink an earlier one
  • --no-install-recommends skips optional extras
  • This step took less than a minute
Package Why
ca-certificates HTTPS downloads fail without it
wget Fetches the Quarto .deb
git Some Quarto extensions want it
python3.12 The interpreter, version 3.12.3 here
python3.12-venv Ubuntu ships venv separately
python3-pip Installs into the virtual environment

Block 4: Quarto

RUN ARCH=$(dpkg --print-architecture) && \
    wget -q "https://github.com/quarto-dev/quarto-cli/releases/download/v1.10.18/quarto-1.10.18-linux-${ARCH}.deb" && \
    apt-get update && \
    apt-get install -y --no-install-recommends ./quarto-1.10.18-linux-${ARCH}.deb && \
    rm quarto-1.10.18-linux-${ARCH}.deb && \
    apt-get clean && rm -rf /var/lib/apt/lists/*
  • Quarto is not in Ubuntu’s package list, so we download the .deb from GitHub
#7 91.74 Setting up quarto (1.10.18) ...
#7 DONE 92.0s
  • 92 seconds, the slowest step in the build
  • ./ tells apt to install the downloaded file, not search its list
  • apt-get update runs again because block 3 deleted the package lists
  • The version 1.10.18 is written out, so everyone builds the same image
    • It appears four times in this step. Change all four to update Quarto
  • dpkg --print-architecture gives arm64 on a Mac and amd64 on most Windows and Linux laptops, so each downloads the right file
  • My laptop has Quarto 1.9.38, but your report renders with the image’s 1.10.18

Block 5: the virtual environment and pip

# Ubuntu protects its own Python installation,
# so we create a virtual environment at
# /opt/venv and install our packages there.
RUN python3 -m venv /opt/venv

# PATH tells the shell where to look for
# programs. Putting /opt/venv/bin first means
# "python" and "pip" refer to the virtual
# environment, without activating it by hand.
ENV PATH="/opt/venv/bin:$PATH"

# We copy requirements.txt on its own, before
# the rest of the project.
COPY requirements.txt /project/requirements.txt
RUN pip install --no-cache-dir -r /project/requirements.txt
  • ENV PATH replaces Lecture 23’s source .venv/bin/activate
  • Ubuntu blocks a system-wide pip install with externally-managed-environment, so we use a virtual environment: Appendix 02
  • COPY puts your requirements.txt inside the image, and pip installs from that copy
  • --no-cache-dir keeps pip’s downloads out of the image
  • The install took less than a minute and produced 53 packages
  • COPY requirements.txt comes before COPY . /project, so editing report.qmd does not rerun this step

Blocks 6 and 7: WORKDIR, COPY ., CMD

# WORKDIR sets the folder that later
# instructions run inside.
WORKDIR /project

# Copy everything else from your repository into
# the image, including report.qmd and the saved
# data snapshot in data/raw/.
# The .dockerignore file next to this one lists
# what stays out.
COPY . /project

# QUARTO_PYTHON points Quarto at the virtual
# environment's Python.
ENV QUARTO_PYTHON=/opt/venv/bin/python
CMD ["bash", "-c", "quarto render report.qmd && mkdir -p output && cp -a report.html output/ && echo 'Rendered report is in output/report.html'"]
  • COPY . /project copies the folder you build from, the . in docker build
    • The next slide shows what stays out
  • QUARTO_PYTHON tells Quarto which Python to use
  • The CMD joins four commands with &&: render, create output/, copy the report there, print a message
  • Quarto renders in /project first, because it cannot clear a folder mounted from your laptop
  • The CMD list starts with bash, which gives us the shell that && needs

Command What it removes
docker ps -a Nothing, it lists all containers
docker rm <id> One stopped container
docker rmi <image> One image
docker system df Nothing, it reports what is using space (df = disk free)
docker system prune Stopped containers, unused networks, dangling images, build cache
docker system prune -a All of the above plus every image not in use
  • The ID comes from docker ps -a, and the first few characters are enough
  • A dangling image has no tag. Rebuilding a tag leaves the old image behind
  • docker run --rm keeps old containers from piling up

docker system prune -a deletes every image no running container is using. Read the prompt before you type y

docker buildx build --platform linux/amd64,linux/arm64 \

Try it yourself at home

Use your clone of the starter. Step 2 takes about a minute

  1. Add seaborn==0.13.2 under duckdb==1.5.5 in requirements.txt
  2. Run docker build -t datasci350-project .
  3. Read the log. Note which steps say CACHED
  4. In the demo chunk of report.qmd, add import seaborn as sns under import duckdb
  5. Add print(f"seaborn {sns.__version__}") under the Loaded print
  6. Build again, then run docker run --rm -v "$(pwd)/output:/project/output" datasci350-project
  7. Open output/report.html and find the line seaborn 0.13.2

Solution and captured output: Appendix 01

What to look for:

  • Steps [1/8] to [4/8] stay CACHED
  • The cache misses at [5/8], because requirements.txt changed
  • Every later step rebuilds, so pip install runs again for less than a minute
  • The second build reruns only COPY . /project and takes seconds
  • The image grows from 347MB to 348MB, and from 53 packages to 54

Summary

What we learned today

  • The starter has a pull script, the saved data, the report and a Dockerfile
  • I grade your container with five commands from a fresh clone (30% of the project)
  • The Dockerfile has seven blocks, from the base image to CMD
  • .dockerignore keeps .git, output/ and .env out of the image
  • COPY requirements.txt comes before COPY . /project, so rebuilds take less than 1 second
  • Without -v, the report is deleted with the container
  • If data/raw/ is not committed, the build works but the run fails
  • A pin that does not exist stops the build
  • docker run -it ... bash lets you look inside the container
  • docker system prune frees disk space
  • Ready-made images help you explore, and Docker Hub lets you share
  • The appendices have the exercise solution and common errors

If git clone, docker build and docker run -v work from a fresh folder and the report opens, the container part of your project is done

Appendix 02: When something goes wrong

IOException: No files found that match [...] life_expectancy.csv

data/raw/ was never committed. Run git add data/raw/ and commit, then check with git ls-files data/raw.

No matching distribution found for duckdb==1.5.9

That version does not exist. Pin one that pip index versions duckdb lists.

ls: output: No such file or directory

You forgot -v. Add -v "$(pwd)/output:/project/output" (${PWD} in PowerShell). Linux prints ls: cannot access 'output'.

error: externally-managed-environment

You ran pip install on Ubuntu’s own Python. Use a virtual environment, as in block 5.

failed to read dockerfile: open Dockerfile

You are in the wrong folder. cd into the folder that has the Dockerfile.

NoSuchKernel: No such kernel named python3

ipykernel is missing from requirements.txt. Add ipykernel==7.2.0 back and rebuild.

toomanyrequests: pull rate limit

Docker Hub allows 100 pulls every six hours without an account, 200 with one. Run docker login and build again

Appendix 03: The complete Dockerfile

# 1. Base image
# FROM chooses the starting point: Ubuntu 24.04,
# the system you saw in the containers lecture.
# We pin the tag to "24.04" rather than "latest".
FROM ubuntu:24.04

# 2. Environment and shell
ENV DEBIAN_FRONTEND=noninteractive
SHELL ["/bin/bash", "-c"]

# 3. System packages
# We do not pin apt versions here. Ubuntu replaces
# a version whenever it ships a security fix, and a
# pin that no longer exists stops the build. The
# base image tag and requirements.txt carry the pins.
RUN apt-get update && apt-get install -y --no-install-recommends \
    ca-certificates \
    wget \
    git \
    python3.12 \
    python3.12-venv \
    python3-pip && \
    apt-get clean && rm -rf /var/lib/apt/lists/*

# 4. Quarto
# Quarto is not in the Ubuntu package list, so we
# download the .deb from GitHub. The version is
# written out in full, so the image you build is
# the image everyone else builds.
RUN ARCH=$(dpkg --print-architecture) && \
    wget -q "https://github.com/quarto-dev/quarto-cli/releases/download/v1.10.18/quarto-1.10.18-linux-${ARCH}.deb" && \
    apt-get update && \
    apt-get install -y --no-install-recommends ./quarto-1.10.18-linux-${ARCH}.deb && \
    rm quarto-1.10.18-linux-${ARCH}.deb && \
    apt-get clean && rm -rf /var/lib/apt/lists/*
  • Starter commit cb64771, with comments trimmed. Your clone has them all
# 5. Python environment
# Ubuntu protects its own Python installation, so
# we create a virtual environment at /opt/venv and
# install our packages there.
RUN python3 -m venv /opt/venv

# PATH tells the shell where to look for programs.
ENV PATH="/opt/venv/bin:$PATH"

# We copy requirements.txt on its own, before the
# rest of the project. Docker caches each layer.
COPY requirements.txt /project/requirements.txt
RUN pip install --no-cache-dir -r /project/requirements.txt

# 6. Project files
# WORKDIR sets the folder that later instructions
# run inside.
WORKDIR /project

# Copy everything else from your repository into
# the image, including report.qmd and the saved
# data snapshot in data/raw/.
# The .dockerignore file next to this one lists
# what stays out.
COPY . /project

# 7. Default command
# We render first and copy afterwards. Quarto
# clears its output folder before writing, and it
# cannot clear a folder Docker mounted from outside.
# QUARTO_PYTHON points Quarto at the venv's Python.
ENV QUARTO_PYTHON=/opt/venv/bin/python
CMD ["bash", "-c", "quarto render report.qmd && mkdir -p output && cp -a report.html output/ && echo 'Rendered report is in output/report.html'"]

Appendix 04: Docker Compose

  • Compose saves the long docker run command in a file:
services:
  report:
    build: .
    image: datasci350-project
    volumes:
      - ./output:/project/output
  • Save it as compose.yaml next to your Dockerfile (docker-compose.yml also works):
docker compose up --build
docker compose down
  • Compose handles the relative path ./output, so you don’t need $(pwd)
  • Compose is mainly for several containers working together, such as a database and an API
  • down removes the container and the network it created
  • Use docker compose (with a space). docker-compose (with a hyphen) is the old command
    • I ran this with Compose v5.1.2
  • The starter has no compose file, so write your own
  • What it printed on my laptop:
docker compose up --build
[...]
 Image datasci350-project Built
 Network starter_default Created
 Container starter-report-1 Started
report-1  | Rendered report is in output/report.html
report-1 exited with code 0

docker compose down
 Container starter-report-1 Removed
 Network starter_default Removed
