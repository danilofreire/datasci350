The Dockerfile, instruction by instruction 🐳

The whole file at a glance

Seven blocks, fourteen instructions, eight build steps

# 1. Base image
FROM ubuntu:24.04

# 2. Build-time settings
ENV DEBIAN_FRONTEND=noninteractive
SHELL ["/bin/bash", "-c"]

# 3. System packages
RUN apt-get update && apt-get install -y [...]

# 4. Quarto
ARG QUARTO_VERSION=1.9.37
RUN ARCH=$(dpkg --print-architecture) && [...]

# 5. Python environment
RUN python3 -m venv /opt/venv
ENV PATH="/opt/venv/bin:$PATH"
COPY requirements.txt /project/requirements.txt
RUN pip install --no-cache-dir -r /project/requirements.txt

# 6. Project files
WORKDIR /project
COPY . /project

# 7. Default command
ENV QUARTO_PYTHON=/opt/venv/bin/python
CMD ["bash", "-c", "quarto render report.qmd && [...]"]
  • Fourteen instructions in seven commented blocks
  • Only eight of them create a filesystem layer, which is why the build log counts [1/8] to [8/8]
  • ENV, ARG, SHELL, and CMD set metadata, so BuildKit does not number them
  • The comments in the real file are longer than the instructions. Read them once, and change only what you need

Lecture 23’s file had five instructions and one job: install two packages, run a script. This one installs an operating system, a document engine, and a Python environment in fourteen

Full listing

Blocks 1 and 2: FROM, ENV, SHELL

Ubuntu 24.04, no questions asked

# We pin the tag to "24.04" rather than "latest".
# "latest" changes over time, and a base image
# that changes breaks reproducibility.
FROM ubuntu:24.04

# DEBIAN_FRONTEND=noninteractive stops apt-get
# from asking questions during the build.
# Nobody is at the keyboard to answer them.
ENV DEBIAN_FRONTEND=noninteractive

# Use bash for the RUN steps below. Docker uses
# the simpler "sh" shell by default.
SHELL ["/bin/bash", "-c"]
  • latest on the Ubuntu repository resolved to 24.04 last year. Today it resolves to 26.04
  • FROM ubuntu:latest in September builds a different operating system in December
  • tzdata is the package that would otherwise stop and ask you for a time zone

hub.docker.com/_/ubuntu, accessed 26 August 2026

  • ENV persists into the running container, so docker run sees it too
  • SHELL changes the shell for every RUN below it, so $(...) and && behave as you expect

ubuntu:24.04 is 139MB on disk here, 30.8MB compressed, against 204MB and 45.9MB for Lecture 23’s python:3.14-slim. It ships no Python at all, and Quarto arrives as a .deb, so we need the full Debian userland

Block 3: RUN apt-get install

System packages in one layer

RUN apt-get update && apt-get install -y --no-install-recommends \
    ca-certificates \
    wget \
    git \
    python3.12 \
    python3.12-venv \
    python3-pip && \
    apt-get clean && rm -rf /var/lib/apt/lists/*
  • One RUN is one layer. Splitting this into six RUN lines would give six layers and a bigger image
  • apt-get clean and rm -rf delete the download cache. They have to run in the same layer, because a later layer cannot shrink an earlier one
  • --no-install-recommends skips optional extras
  • This step took 70.8 seconds cold
Package Why
ca-certificates HTTPS downloads fail without it
wget Fetches the Quarto .deb
git Some Quarto extensions want it
python3.12 The interpreter, version 3.12.3 here
python3.12-venv Ubuntu ships venv separately
python3-pip Installs into the virtual environment

An older version of this lecture pinned every apt package by hand, and the build broke the week Ubuntu shipped a security update, because the pinned version no longer existed in the archive. The starter pins the base image tag and the Python packages instead, and lets apt give you the current patch of each system package

Block 4: Quarto

ARG, dpkg --print-architecture, and a .deb

ARG QUARTO_VERSION=1.9.37
RUN ARCH=$(dpkg --print-architecture) && \
    wget -q "https://github.com/quarto-dev/quarto-cli/releases/download/v${QUARTO_VERSION}/quarto-${QUARTO_VERSION}-linux-${ARCH}.deb" && \
    apt-get update && \
    apt-get install -y --no-install-recommends "./quarto-${QUARTO_VERSION}-linux-${ARCH}.deb" && \
    rm "quarto-${QUARTO_VERSION}-linux-${ARCH}.deb" && \
    apt-get clean && rm -rf /var/lib/apt/lists/*
  • Quarto is not in the Ubuntu package list, so we download the .deb from GitHub
  • The build printed this near the end of the step:
#8 206.0 Setting up quarto (1.9.37) ...
#8 DONE 206.5s
  • 206.5 seconds, the slowest step in the whole build
  • The ./ in front of the filename tells apt to install a local file rather than search the archive
  • apt-get update runs a second time because block 3 deleted the package lists
  • ARG is a build-time variable. Override it without editing the file:
docker build --build-arg QUARTO_VERSION=1.9.38 \
  -t datasci350-project .
  • ARG disappears when the build ends. ENV stays in the running container
  • dpkg --print-architecture printed arm64 on my Mac, amd64 on most Windows and Linux laptops. The same Dockerfile fetches the other file

This laptop has Quarto 1.9.38. The image has 1.9.37, because that is what the ARG says. The version inside the image renders your report, and it is the one I will run

Block 5: the virtual environment and pip

The layer order that makes rebuilds fast

# Ubuntu protects its own Python installation,
# so we create a virtual environment at
# /opt/venv and install our packages there.
RUN python3 -m venv /opt/venv

# PATH tells the shell where to look for
# programs. Putting /opt/venv/bin first means
# "python" and "pip" refer to the virtual
# environment, without activating it by hand.
ENV PATH="/opt/venv/bin:$PATH"

# We copy requirements.txt on its own, before
# the rest of the project.
COPY requirements.txt /project/requirements.txt
RUN pip install --no-cache-dir -r /project/requirements.txt
  • This is Lecture 23’s venv slide, moved inside an image. The ENV PATH line replaces source .venv/bin/activate
  • Ubuntu refuses a system-wide pip install and tells you to make a virtual environment. The error is externally-managed-environment: Appendix 02
  • --no-cache-dir stops pip keeping a copy of every wheel inside the image
  • The install took 89.2 seconds and produced 54 packages
  • COPY requirements.txt sits alone above COPY . /project so that editing report.qmd leaves this slow step cached

That ordering is the most useful thing in the file, and it pays off on the rebuild slide: jump there

Blocks 6 and 7: WORKDIR, COPY ., CMD

Rendering into /project, copying into output/

# WORKDIR sets the folder that later
# instructions run inside.
WORKDIR /project

# Copy everything else from your repository into
# the image, including report.qmd and the saved
# data snapshot in data/raw/.
# The .dockerignore file next to this one lists
# what stays out.
COPY . /project

# QUARTO_PYTHON points Quarto at the virtual
# environment's Python.
ENV QUARTO_PYTHON=/opt/venv/bin/python
CMD ["bash", "-c", "quarto render report.qmd && mkdir -p output && cp -a report.html output/ && echo 'Rendered report is in output/report.html'"]
  • COPY . /project copies the build context, which is the folder you named with the . in docker build. The next slide keeps things out of it
  • Without QUARTO_PYTHON, Quarto looks for a system Python and misses the packages you installed
  • The CMD is three commands joined with &&: render, make output/, copy the HTML in
  • Quarto clears its output folder before writing, and it cannot clear a folder Docker has mounted from outside. Rendering into /project and copying afterwards avoids that

Lecture 23’s CMD ["python", "hello.py"] was the same exec form: a JSON array of strings, with no shell involved. Here the array starts bash, and bash provides the shell we need for &&

Part What it does
--rm Deletes the container when it exits
-v host:container Connects a folder on your machine to one inside the container
datasci350-project The image to start
  • -v is short for volume. The left side of the colon is your laptop, the right side is the container
  • $(pwd) is your current folder. PowerShell wants ${PWD} and the old Windows terminal wants %cd%
  • The path on the left must be absolute, which is why nobody writes -v ./output:...
  • The report is the only thing that survives the container, and it survives because of that flag

docker run creates a container from the image and starts it. With --rm it is gone before you finish reading the output

Forgetting the mount

The report renders and then vanishes

docker run --rm datasci350-project

[...]
Output created: report.html

Rendered report is in output/report.html

ls output
ls: output: No such file or directory
exit code: 1
  • The container said it succeeded. It did succeed
  • It wrote /project/output/report.html inside itself, --rm deleted the container, and the file went with it
  • Nothing on your laptop changed
  • The file really existed. Here it is, listed from inside the same container before it exited:
docker run --rm datasci350-project bash -c \
  "quarto render report.qmd >/dev/null 2>&1 \
   && mkdir -p output && cp report.html output/ \
   && ls -la output"

-rw-r--r-- 1 root root 1313598 report.html
  • The same 1,313,598 bytes as the mounted run produced
  • This is the most common Docker mistake in the course, and the terminal gives you no warning at all

Success inside a container that no longer exists is worth nothing to you. Check ls output after every run, and check the timestamp on the file

What to look for:

Inspecting a container that misbehaves

docker run -it and what it tells you

  • Anything after the image name replaces the CMD, so this starts a shell instead of rendering:
docker run --rm -it datasci350-project bash
  • Then look around, the way you would on any Linux machine:
quarto --version
1.9.37

which python
/opt/venv/bin/python

python -c "import polars, duckdb, matplotlib; \
  print(polars.__version__, duckdb.__version__, \
        matplotlib.__version__)"
1.43.2 1.5.5 3.10.8

ls data/raw
life_expectancy.csv
life_expectancy_raw.json

pwd
/project

whoami
root
  • Seven answers to the seven questions you actually have when a render fails: which Quarto, which Python, which packages, is the data there, where am I, who am I
  • -i keeps standard input open and -t gives you a terminal. Together they make an interactive session
  • docker exec -it <container> bash does the same on a container that is already running
  • Anything you install in there disappears when the container exits. Fix requirements.txt and rebuild instead
  • docker logs <container> prints the output of a container you started without watching

This is the fastest way to settle an argument about whether a package is in the image. Ten seconds inside the container beats ten minutes of reading the Dockerfile

Command What it removes
docker ps -a Nothing, it lists containers including exited ones
docker rm <id> One stopped container

docker system prune -a All of the above plus every image not in use

  • --rm on docker run is what stops the container list growing in the first place

docker system prune -a deletes every image no running container is using, including the one you spent seven minutes building. Read the prompt before you type y

Docker Compose

The same build and run, written down once

  • Typing docker run --rm -v "$(pwd)/output:/project/output" datasci350-project twenty times is how typos happen:
services:
  report:
    build: .
    image: datasci350-project
    volumes:
      - ./output:/project/output
  • Save it as compose.yaml next to your Dockerfile:
docker compose up --build
docker compose down
  • Compose reads the relative path ./output for you, so $(pwd) never appears
  • Compose exists for multi-container work: a database, an API, and a notebook talking to each other. One service is the small end of it

Appendix 02: When something goes wrong

Seven errors from this lecture’s build

FileNotFoundError: [...] life_expectancy.csv

The snapshot never reached the repository. Run git add data/raw/, commit, and check with git ls-files data/raw.

No matching distribution found for polars==1.43.9

That version does not exist on PyPI. Run pip index versions polars and pin one it lists.

ls: output: No such file or directory

You ran the container without -v. Add -v "$(pwd)/output:/project/output", or ${PWD} in PowerShell.

error: externally-managed-environment

You ran pip install against Ubuntu’s own Python. Create a virtual environment and put /opt/venv/bin first in PATH.

failed to read dockerfile: open Dockerfile

You are in the wrong folder. The . in docker build -t name . is where Docker looks, so cd into the folder with the Dockerfile.

NoSuchKernel: No such kernel named python3

ipykernel is missing from requirements.txt, so Quarto cannot start a kernel. Put ipykernel==7.2.0 back and rebuild.

toomanyrequests: pull rate limit

Docker Hub allows 100 anonymous pulls per hour from one address. Run docker login and build again.

Appendix 03: The complete Dockerfile

As shipped in the starter

# 1. Base image
# FROM chooses the starting point: Ubuntu 24.04,
# the system you saw in the containers lecture.
# We pin the tag to "24.04" rather than "latest".
FROM ubuntu:24.04

# 2. Build-time settings
ENV DEBIAN_FRONTEND=noninteractive
SHELL ["/bin/bash", "-c"]

# 3. System packages
# We do not pin apt versions here. Ubuntu replaces
# a version whenever it ships a security fix, and a
# pin that no longer exists stops the build. The
# base image tag and requirements.txt carry the pins.
RUN apt-get update && apt-get install -y --no-install-recommends \
    ca-certificates \
    wget \
    git \
    python3.12 \
    python3.12-venv \
    python3-pip && \
    apt-get clean && rm -rf /var/lib/apt/lists/*

# 4. Quarto
ARG QUARTO_VERSION=1.9.37
RUN ARCH=$(dpkg --print-architecture) && \
    wget -q "https://github.com/quarto-dev/quarto-cli/releases/download/v${QUARTO_VERSION}/quarto-${QUARTO_VERSION}-linux-${ARCH}.deb" && \
    apt-get update && \
    apt-get install -y --no-install-recommends "./quarto-${QUARTO_VERSION}-linux-${ARCH}.deb" && \
    rm "quarto-${QUARTO_VERSION}-linux-${ARCH}.deb" && \
    apt-get clean && rm -rf /var/lib/apt/lists/*
# 5. Python environment
# Ubuntu protects its own Python installation, so
# we create a virtual environment at /opt/venv and
# install our packages there.
RUN python3 -m venv /opt/venv

# PATH tells the shell where to look for programs.
ENV PATH="/opt/venv/bin:$PATH"

# We copy requirements.txt on its own, before the
# rest of the project. Docker caches each layer.
COPY requirements.txt /project/requirements.txt
RUN pip install --no-cache-dir -r /project/requirements.txt

# 6. Project files
# WORKDIR sets the folder that later instructions
# run inside.
WORKDIR /project

# Copy everything else from your repository into
# the image, including report.qmd and the saved
# data snapshot in data/raw/.
# The .dockerignore file next to this one lists
# what stays out.
COPY . /project

# 7. Default command
# We render first and copy afterwards. Quarto
# clears its output folder before writing, and it
# cannot clear a folder Docker mounted from outside.
# QUARTO_PYTHON points Quarto at the venv's Python.
ENV QUARTO_PYTHON=/opt/venv/bin/python
CMD ["bash", "-c", "quarto render report.qmd && mkdir -p output && cp -a report.html output/ && echo 'Rendered report is in output/report.html'"]
  • The starter is at commit 7d79f5b, plus the .dockerignore and comment fix made for this lecture
  • Comments are trimmed here. The file in your clone explains every line
